## 1. 全景图

```text
┌─ dsh 宿主（契约一律见 docs/ref/，本文不复述）────────────────────────────────────────
│  [日志] 会话日志 session/event：持久事件 user/message / assistant/message / turn/end
│  [循环] Agent 实时事件：agent/created / agent/inbox/claimed / agent/disposed
│  [装配] system-prompt/assemble waterfall：每步系统提示词装配（agent 定域分发）
│  [工具] ctx.tools：defineTool 注册表（exec.signal / 规范 JSON 输出）
│  [模型] ctx.llm：provider 无关流服务（适配器失败收敛为终态 error/aborted finish 块）
│  [存储] ctx.storage：后端注册表 + KvUnit（单次写原子且持久；并发写顺序由调用方负责）
└───────────────────────────────────────────────────────────────────────────────
        │
        │ 持久事件 = 记忆的唯一来源（[日志]）；[循环] 提供定域生命周期与查询提示
        ▼
┌─ dsh-mem 插件 ────────────────────────────────────────────────────────────────
│  (0) 作用域层 scope（src/scope.ts，M2）：session.header.cwd → scope 键（归一
│        化路径 FNV-1a 8-hex）→ unit 名 dsh_mem_ws_<hash>；ScopeRegistry 惰性
│        开启每作用域一套 (2)~(7)；无 cwd 回退 storage.unit 本名
│  (1) 观察层 observeSessions / observeAgents + intake 过滤（src/runtime.ts、src/intake.ts）
│        │  intake.session.acceptSourceKinds 配置"什么算人类输入"（默认 ['user']）；
│        │  带 form 的消息（插件上下文）恒不算对话（M3）
│        │  pending / recent 双缓冲；turn/end 取走本轮批次，fire-and-forget 进入写入
│        ▼
│  (2) 写入管线 write-path + judges（src/write-path.ts）
│        │  候选抽取、M5 判分、矛盾判定 ──▶ [模型] ctx.llm
│        │  幸存候选批量嵌入 ──▶ (E) 外部端点 /embeddings
│        │  写入结果累计 newSinceSleep 计数 ──▶ (6) 触发门控
│        ▼
│  (3) 记忆库 memory-store + vector-store（src/memory-store.ts；按工作区一区一库，M2）
│        │  putRecord / putNode / softInvalidate(含节点) / refresh* / retrievableAt ──▶ [存储] KvUnit
│        │  检索宇宙 = 有效未压缩记录 + 有效节点（INV-3）；睡眠/计分/写入按作用域各自实例
│        ▼
│  (4) 检索管线 retrieval + metrics（src/retrieval.ts）
│        │  L0 余弦召回 → CSLS → cross-encoder 精排 → MMR
│        │  查询向量与精排 ──▶ (E) 外部端点 /embeddings 与 /rerank
│        ├──▶ (5a) 自动注入通道：agent 定域 assemble 监听 ──▶ [装配] push 'dsh-mem'
│        └──▶ (5b) 主动召回通道：memory_search 工具 ──▶ [工具] ctx.tools
│
│  (6) 睡眠巩固周期 sleep-cycle + judges（src/sleep-cycle.ts；turn/end 门控触发）
│        │  聚类 → gist 抽取 / QA 生成 / gist 作答 / 兼容复核 ──▶ [模型] ctx.llm
│        │  gist 与探针嵌入 ──▶ (E) /embeddings；建/挂节点与压缩归档 ──▶ (3)
│        │  第 7 步全库邻域刷新 + S 兜底衰减（无簇也执行）
│
│  (7) 评分引擎 scoring（src/scoring.ts，P2 支柱一 S 完整动态）
│        │  两条检索通道的使用/抑制事件 → S 增益/惩罚（arousal 乘法门）──▶ (3)
│        │  层级跃迁触发 M5 重判（EMA）──▶ [模型] ctx.llm；被睡眠周期调用的纯衰减函数无 LLM
│
│  (E) 插件自有外部端点（dsh 无此 seam，插件自有依赖）：
│      /embeddings（OpenAI 兼容）与 /rerank（Cohere/Jina 式）；embedding.ts 客户端，
│      deterministic 模式为离线替身（只验证管线连通，数值无语义意义）
└───────────────────────────────────────────────────────────────────────────────
```

数据只有一个入口（会话日志事件 → 写入管线）、两个默认开启的模型可见出口（自动注入 section、memory_search 工具）加一个默认关闭的开发/测试出口（memory_clear 硬删除工具，§9.4）、一条离线支路（睡眠周期 → 语义层迁移）和一条评分支路（检索事件 + 离线衰减 → S → 分层门控）。时间戳不参与检索排序或删除（INV-1 的精确边界见 §3.3，含 P2 兜底衰减例外与时间旅行重建）。

### 2.2 通道选择依据（与设计的差异记录）

设计 §5.0 首选 `ctx.systemPrompt.section()` 作为自动通道。实现改用 **`system-prompt/assemble` waterfall（agent 定域）**，原因：`PromptSection.text` 的 provider 签名是**同步**的（`string | ((context) => string)`，见 `@deepseek-ai/dsh-system-prompt/lib/types/index.d.ts`），承载不了异步检索链路。`system-prompt/assemble` 整体装配变换是 ref 官方文档同章节列出的扩展点（extension-cookbook：「系统提示词可配置性」行及 assemble 专段），且功能→机制映射的「记忆」行由 section 提供方 + 工具两条通道共同满足——本插件的 waterfall 监听器就是该 section 的异步等价物。此差异已在 README「实现选择说明」声明，此处为唯一权威记录。

### 2.3 规范符合性审核结论（2026-10-24，P0 全项 + P1/P2 增量）

| 审核项 | 结论 | 依据 |

## 3. 数据模型（实现层）

定义在 `src/types.ts`；此处记录**实现语义**（与设计 §4 的差异以本文为准）。

### 3.1 MemoryRecord（episodic 表）

| 字段 | 类型 | P0–P2 实现语义 |
|---|---|---|
| `id` | UUID v4 | 不可变（C-4）；`crypto.randomUUID()` 生成 |
| `text` | string | 自包含第三人称陈述；写入前对库内 valid 记录查重（§5.3） |
| `embedding` | number[] | L2 归一化后落库（C-6）；维度 = `config.embedding.dimensions` |
| `imp` / `valence` / `arousal` | number | M5 判分输出，经夹取（imp 1–10 整数、valence −1..1、arousal 0..1）；**P2 起层级跃迁时重判并按 EMA 混入**（§10.4） |
| `epi` | number [0,1] | 写入时 = **词法近似**（实体+时间表达密度 sigmoid 合成，`epiLexical`）；睡眠周期的完整 M6 公式（z 化 + G 探针）只用于 gist（§7.5），不回写成员 |
| `r_m` / `red` | number | 邻域统计；`r_m` = 检索宇宙 top-`retrieval.cslsK` 近邻平均余弦，`red` = top-5 近邻平均余弦（§4.5）；写入时算新记录自身，全库刷新由睡眠周期第 7 步承担（B-2） |
| `tier` | hot/warm/cold | 由 S 与 `tier.hotThreshold/coldThreshold` 派生（`tierOf`）；**P2 起随 S 动态跃迁**（使用/抑制/衰减路径都重算）；检索时的唯一分层消费是 cold 门控（§6.2） |
| `con_route` | attached / new_node / pending | P0 恒为 pending；P1 起由睡眠周期迁移步骤写入（new_node → `{kind:'new_node',nodeId}`，attached → `{kind:'attached',nodeIds:[nodeId]}`） |
| `links` | MemoryLink[] | `supersedes`（矛盾时指向被软失效者——**P2 起目标可为语义节点 id**）/ `complements`（补充时指向被补充者，目标同样可跨层）；`related` 尚无生产方 |
| `S` | number | P0 初始化为 imp；**P2 起完整动态**：使用增益 α·(1+cue)·g(arousal)、抑制惩罚 ε、兜底衰减 e^(−Δt/τ)（全部经 scoring.ts，§10） |
| `counters` | ScoreCounters | used_count / suppressed_count / last_used_at? / last_cue_quality? / **last_decay_at?**（P2：兜底衰减锚点，缺省回退 created_at）。P0–P1 仅记账；**P2 起被 S 动态消费** |
| `time_meta` | created_at / valid_at / invalid_at? / **compressed_at?** | 纯元数据（INV-1）；`invalid_at` 是唯一的失效标记；`compressed_at`（P2）= 归档时点，时间旅行视图据此判定"当时是否还在检索宇宙"（§4.4） |
| `flags` | superseded_by? / compressed_into? / qa_passed? / incompressible? | `incompressible`：QA/epi 闸门拒收标记，全簇标记后需新成员加入才重试（§7.4）；`compressed_into` + `qa_passed` 由迁移写入（§7.6） |
| `origin` | {session_id, turn, seq} | 溯源审计用，可选 |

### 3.2 SemanticNode（semantic 表，P1 起填充）

| 字段 | P0–P2 实现语义 |
|---|---|
| `id` / `gist` / `embedding` | UUID；LLM 蒸馏的自包含摘要（§7.3）；归一化向量（C-6） |
| `epi` | gist 的**完整 M6 epi**（z 词法特征 − z(G 探针)），迁移闸门输入 |
| `links` / `member_refs` | P1 无 links 生产方；`member_refs` = 被压缩归档的成员记录 id（迁移时写入，挂入时追加） |
| `S` | 新建 = 簇均 `imp`；被挂入时 `S += sleep.attachGain`；**P2 起叠加完整动态**：使用/抑制事件与兜底衰减同记录侧（无 arousal 门、无 M5 重判，§10） |
| `counters?` | **P2 新增可选字段**：与记录同构的 ScoreCounters（旧节点缺省按全 0 容忍，首个事件起写全） |
| `superseded_by?` | **P2 新增可选字段**：被新记忆推翻时指向取代者（写入路径矛盾判定指向节点时写入，§5.2）——与记录 `flags.superseded_by` 同义 |
| `r_m` | 与检索宇宙 top-k 近邻的平均余弦，第 7 步刷新（新建时置 0 后统一刷新） |
| `time_meta` | 同记录语义；**P2 起节点软失效有生产方**（写入路径判定，B-6 关闭）：`invalid_at` + `superseded_by`，节点退出检索宇宙与索引、本体永不删除；成员记录保持归档状态 |
| tier（派生） | 不落盘：`retrievable()` / `retrievableAt()` 视图按 `tierOf(node.S)` 现算 |

### 3.3 数据不变量（全库强制）

- **INV-1 时间中立（精确边界，P2 修订）**：时间戳永不作为检索**排序**或**删除**的输入。三个设计明文例外：(a) **兜底衰减**（§2.1 工程保险：S·e^(−Δt/τ)，只影响分层、永不触发删除——这是全系统唯一的时间驱动"分数"变化）；(b) **时间旅行池选择**（§2.5 完整版：valid_at/invalid_at/compressed_at 区间重建某时点的检索宇宙，是有效性元数据的投影，不参与排序权重）；(c) M4 con 基线窗口按 `created_at` 取最近 `sleep.conWindow` 条（§3.4 固定的"滚动分布"统计基线，非记忆排序）。设计 §2.4 的「查询含时间意图时启用 recency 特征」仍未实现。
- **INV-2 只软失效不删除**：失效 = 设 `time_meta.invalid_at` + 取代者指针（记录 `flags.superseded_by` / 节点 `superseded_by`）并移出索引；记录与介质行永存。P2 起记录与语义节点都有失效生产方（写入路径矛盾判定，时间重叠闸门控）。**唯一例外**：`MemoryStore.clearAll()`（§4.4）——memory_clear 工具（§9.4，`config.tool.clear` 显式开启的开发/测试硬删除）触达的按键 `deleteRecord` 双表全清，含软失效与已归档记录，时间旅行不可回溯。
- **INV-3 索引与检索宇宙双层视图**：VectorIndex 含**全部有效 episodic 记录（含已压缩归档者）+ 全部有效语义节点**；消费侧三个过滤视图——`similar()`（写入路径矛盾判定）= 有效记录**含已压缩**（归档记忆仍可被新信息软失效，P0 安全网不因 P1 迁移而退化）；`similarNodes()`（P2，同判定的第二路）= 有效语义节点；`retrievable()`/`searchRetrievable()`（检索宇宙）= 有效**未压缩**记录 + 有效节点。软失效项在所有视图中都被排除。
- **INV-4 先持久化后镜像**：任何写操作先 `await unit.putRecord(...)` 成功，再更新内存 Map 与索引（记录与节点同规）；镜像与介质不会出现「镜像有、介质无」。
- **INV-5 嵌入归一化**：落库与入索引前都经 L2 归一化（`embedding.ts` 服务端归一 + `vector-store.ts` 入索引再归一，双保险）；余弦因此等价于点积。记录、节点 gist、M6 探针向量同规。
- **INV-6 压缩归档语义**：`compressed_into` 指向承接 gist 的节点，`time_meta.compressed_at`（P2）记录归档时点（与 flag 同笔写入）；成员记录退出检索宇宙但保留在存储与 `similar()` 视图中（INV-3），回溯经 flag 索引原记录。QA/epi 闸门拒收 → 全簇 `incompressible: true`，**拒收不是失败**：簇保留原状，需新成员加入（聚类池要求至少一名未标记成员）才会重试。
- **INV-7 惰性衰减等价性（P2）**：兜底衰减以 `counters.last_decay_at`（缺省 `created_at`）为锚按 elapsed 指数衰减，事件路径先补衰减再加/减事件增量、锚点前移到事件时刻——指数衰减可乘复合，故与「逐日衰减 + 事件增量」数学等价，且不需要任何定时器。

## 4. 存储层（src/memory-store.ts、src/vector-store.ts）

### 4.1 KV unit 形状（M2 起：按工作区派生）

```
scope 键 = normalizeWorkspacePath(session.header.cwd) 的 FNV-1a 8 位十六进制
           （归一化：反斜杠→正斜杠、统一小写、去尾部分隔符——Windows 大小写/分隔符不敏感）
unit 名 = scopeKey === undefined（无 cwd / workspaceScope=false）
           ? config.storage.unit（默认 'dsh_mem'，回退 unit，向后兼容）
           : `<config.storage.unit>_ws_<scopeKey>`（如 dsh_mem_ws_f02fc950）
descriptor = { name: unitName（连字符归一为下划线，归一后须匹配 /^[a-z][a-z0-9_]*$/
               ——与宿主 UNIT_NAME_RE 一致，不合规在启动期抛错；M2 起由
               memoryUnitDescriptor(unitName, config) 参数化接收）,
               version: config.storage.version (默认 1),
               tables: ['episodic', 'semantic'], hasGlobal: false }
```

- 表→记录：episodic 存 MemoryRecord、semantic 存 SemanticNode，键 = 记录/节点 id，**无 global 槽**。
- **M1 起生产部署用 sqlite 后端**（`dsh-storage-sqlite`，一个库文件承载全部 unit；后端包须与宿主版本精确对齐，见 §17）；json 后端仍受支持（回退/单测）。旧 `dsh_mem.json` 时代的介质不迁移（deterministic 嵌入无语义价值），原地保留。
- 版本契约：开库时介质版本 ≠ descriptor.version → 宿主抛 `version-mismatch`（宿主契约）。P1 只向记录/节点新增可选字段（旧记录缺字段按 undefined 容忍），**version 保持 1 即可**；真正不兼容的变更（含更换嵌入模型/维度）仍须 bump version 或清空旧 unit（B-5）。**M2 注意**：更换 scope 哈希算法或 unit 命名规则等于换库（旧工作区 unit"消失"、新 unit 空开），属不兼容变更。

### 4.2 内存镜像与索引

`MemoryStore.open()` 全量 `loadAll()` 后逐表最小形状校验（记录：id/text string + embedding number[]；节点：id/gist string + embedding number[]；不合规跳过并 warn 一次，不抛错），重建两个 Map 与索引（按 INV-3 的全集口径：valid 记录含压缩者 + valid 节点）。

### 4.3 并发模型（内部契约 C-1，必读）

宿主 KvUnit 契约明确：**单次调用原子且 resolve 即持久，但不串行化并发写——写顺序由调用方负责**（`dsh-storage` backend.d.ts）。插件据此确立：

- **C-1a 镜像读改写在前、await 在后**：`updateRecord` 的「读镜像 → fn → 计算新值」全部同步完成于首个 await 之前，单条 JS 任务内不会交错。
- **C-1b 单管线内串行**：写入管线对候选逐条 await；睡眠周期对簇逐个、对成员逐条 await；`softInvalidate` 幂等。
- **C-1c 跨链竞争（所有者已接受的取舍）**：进程内现有**三条**独立 fire-and-forget 写链——写入管线（每 turn/end）、S 记账 `ScoreKeeper.recordRetrieval`（两条检索通道触发，含跃迁时的 M5 重判 LLM 调用）、睡眠周期（门控触发，含第 7 步衰减写）。跨链对同一记录并发 `updateRecord` 存在丢失更新窗口；最坏损失是一次 flag/计数/S 增量，可被下一周期自愈。该取舍由 README「已知接受的取舍」段声明为准；若日后需精确，应为 MemoryStore 增加每记录写链（对齐 storage-domain 的单链纪律）。

### 4.4 查询接口与视图

| 接口 | 视图 | 消费方 |
|---|---|---|
| `similar(vector, k)` | 有效 episodic 记录（**含已压缩**），经索引 filter + 镜像复核 | 写入路径矛盾判定（§5.2）第一路；这就是压缩记忆仍可被推翻的安全网 |
| `similarNodes(vector, k)`（P2） | 有效语义节点，同款 filter + 复核 | 写入路径矛盾判定（§5.2）第二路——gist 被新记忆推翻的安全网（B-6 关闭） |
| `retrievable()` / `searchRetrievable()` | **检索宇宙**：有效未压缩记录 + 有效节点（节点 tier 由 S 现算） | 检索管线 L0（§6.1）、邻域统计（§4.5）、聚类池与 con 基线（§7） |
| `retrievableAt(t)`（P2） | **时点重建的检索宇宙**：`valid_at ≤ t < invalid_at` 且当时未压缩（`compressed_at` 未设或 > t）的记录 + 当时有效的节点 | 检索管线 `at` 选项（§6.4）、memory_search 时间旅行（§9）、eval-semtime 复活计数 |
| `validMemories()` / `validNodes()` | 全部有效记录/节点（不过滤压缩） | 睡眠周期聚类池（自行再滤 compressed）、启动日志计数、S 兜底衰减批处理（§10.3） |
| `clearAll()`（开发/测试，唯一写侧硬删除） | **不是视图**：双表逐键 `deleteRecord` 硬删除（含软失效与已归档记录），镜像与索引同步清空、返回删除计数 | memory_clear 工具（§9.4，`config.tool.clear` 门控；INV-2 唯一例外） |

- `retrievableAt` 的近似边界：tier / r_m / 节点 gist 取当前落盘快照（历史 S 与邻域不重建）；P1 遗留的无 `compressed_at` 归档记录保守视为"历来已压缩"（无法定期则不复活）；节点成员集历史不重建（挂入只追加 member_refs）。
- **软失效写入**：记录 `softInvalidate(id, supersededBy, at)` 与节点 `softInvalidateNode(id, supersededBy, at)`（P2）同款幂等语义——已失效则保持首次时间戳不抛；节点版写 `time_meta.invalid_at` + `superseded_by` 并退出索引与检索宇宙。

### 4.5 邻域统计 `refreshNeighborhood(id,k)` / `refreshNodeNeighborhood(id,k)`

- 近邻取自**检索宇宙**（§4.4），即 r_m/red 所服务的 CSLS/聚类视图；
- 取 `max(k,5)+1` 个近邻（+1 容纳自身），**排除自身**后截断；
- `r_m` = 前 k 个近邻平均余弦（不足取实际数），`red` = top-5 平均余弦；
- 5 是设计 §3.3 公式的固定宽度，**非可调参数**（源码常量 `RED_NEIGHBOR_TOP`）；
- 结果写回并持久化。**B-2 周期间漂移窗口**：写入路径只刷新新记录自身；全库（含节点 r_m）刷新由睡眠周期第 7 步承担（§7.7）——两次周期之间，既有记录的 r_m/red 随新写入逐渐失真，检索侧消费的是最近一次刷新的快照。

### 4.6 向量索引（vector-store.ts）

精确 kNN 暴力扫全量（P0 规模选择；`VectorIndex` 接口为 ANN 预留；睡眠聚类是 O(n²) pairwise，同规模假设）。同步签名是有意契约；平局以 id 字典序决胜，保证可复现。`putRecord`/`putNode`/`updateRecord`/`softInvalidate` 都经 `syncIndex` 的 remove-then-conditionally-add 语义维护索引。

### 4.7 工作区作用域与 ScopeRegistry（M2）

**隔离模型**：一个 scope = 一个 KvUnit = 一套完整 ScopedRuntime（store / retriever / write / sleep / scores + 各自的 `newSinceSleep`/`sleeping` 门控）。物理隔离——任何代码路径忘记过滤都不可能跨工作区泄露，因为别的工作区的数据不在这个 unit 里。睡眠聚类宇宙 = 本工作区记忆（语义上也更正确：跨工作区记忆不应聚类）。

**scope 解析**（src/scope.ts）：
- 写入路径：`session/event` 回调里 `scopeKeyOfSession(session)` → `session.header.cwd`（宿主验证过的绝对路径，创建期元数据、会话期间不变）；会话首事件解析一次缓存在 SessionState.scopeKey。
- 读取路径（自动注入与 memory_search）：`scopeKeyOfAgent(agent)` → `agent.session.header.cwd`——首个装配可能先于任何 session 事件（M2 顺带修复了 P0 的边界：原来 `!state` 直接跳过注入，现在首轮也能注入）。
- `storage.workspaceScope=false` → 恒 undefined（全局单库旧行为）；无 cwd 会话 → undefined → 回退 `storage.unit` 本名。

**ScopeRegistry**：`Map<cacheKey, Promise<ScopedRuntime>>` 缓存 open Promise（并发 get 共享同一次 open）；open 失败不缓存（下次事件重试）并经 onOpenError 旁路记日志——单个工作区开库失败只影响该工作区的事件，不拖垮其他工作区；`ctx.effect` 注册 `closeAll()`（卸载/HMR 时统一关闭含在途 open 完成后的全部作用域）。`\0fallback` 缓存前缀保证回退槽与 8-hex scope 键永不碰撞。

## 5. 写入管线（src/write-path.ts、src/judges.ts）

*P2 增量：矛盾判定升级为完整版（时间重叠闸 + 语义节点可被推翻）；其余流程不变。*

### 5.1 触发与批处理（runtime.observeSessions）

```
session/event(user/message, isConversationMessage 通过) ─┐
session/event(assistant/message) ────────────────────────┤→ pending[] + recent[] 双缓冲
session/event(turn/end) → 取走 pending 批次 → scopedFor(state.scopeKey)
                                            └→ fire-and-forget processTurn
                                               完成后累计该作用域触发计数 → maybeSleep(rt)
```

- **M3 起"什么算人类输入"由 `intake.session.acceptSourceKinds` 配置**（默认 `['user']`；IM 适配器以自定义 kind 注入消息时加进列表即可）；**form 守卫**：带 `form` 的消息（instructions/catalog/snapshot/notice/relay/recall——dsh-llm MessageSource 契约的"上下文"轴）恒不算对话，无论 kind 是否匹配。`intake.session.enabled=false` 时整条会话观察不注册（停写不停检索）。assistant 消息恒进缓冲（对话另一半）。
- 每会话的 scope 键在首事件时由 `session.header.cwd` 解析一次（M2），turn/end 按该作用域路由写入。
- `recent` 上限 = `write.messageWindow × 2` 条（滑动窗口），供查询扩展与工具侧 recentTurns 消费；`watermark` 已记录但目前无消费方（B-7）。
- **turn/end 处理是 fire-and-forget**：写入永不阻塞回合计时；失败仅记日志。
- 事件数据形状（经 dsh-session 类型确认）：`user/message` 的 data 即 UserMessage；`assistant/message` 的 data 为 `{turn, step, message, usage?}`（取 `.message`）；`turn/end` 的 data 为 `{turn, reason}`（取 `.turn`）。

### 5.2 每轮七步（WritePipeline.processTurn）

对窗口内消息（最多 `write.messageWindow` 条）：

1. **候选抽取**：1 次 ctx.llm 调用，返回 ≤ `write.maxCandidates` 条自包含陈述（非数组即重试）。
2. **去重**：对库内 **valid** 记录文本集合 + 本批已见集合做精确匹配去重（被软失效的同文记录不阻止重写）。
3. **嵌入**：全部幸存候选**一次批量**调用（`embedding.batchSize` 分片）。
4. **逐候选串行**，每条：
   a. M5 rubric 判分（1 次 ctx.llm）→ `imp < write.minImportance` 则 dropped；
   b. 近邻查询（同步 kNN）：**两路**——`similar()`（`write.contradictionTopK` 个且 cos ≥ `write.contradictionMinCos` 的 valid 记录，**含已压缩归档者**，§4.4 安全网）⊕ `similarNodes()`（同参数的有效节点 gist），**记录在前、节点在后**拼接送判 → 矛盾判定（1 次 ctx.llm，一次调用判全部近邻）；
   c. verdict 分派（§2.5 完整版）：
      - `duplicate` → dropped（NOOP）；
      - `contradicts` 且 `temporal === 'disjoint'` → **不软失效不建链**（不同时期的矛盾两条都真，如"过去用 MySQL"vs"现在用 PostgreSQL"）；
      - `contradicts` 且 overlapping/缺省 → 目标为节点则 `softInvalidateNode`、为记录则 `softInvalidate`，新记录建 `supersedes` 边（可跨层）；
      - `complements` → 建 `complements` 边（可跨层）；`unrelated`/无近邻 → 直接入库；
   d. `putRecord`（S=imp 初始化、tier 定型）→ `refreshNeighborhood`。
5. **失败语义**：单候选任何一步失败 → dropped+1、记日志、**不中断整轮**；`signal` 已中止则原样上抛。

成本口径（对齐设计 §5.4）：每轮 1 次抽取调用 + 每条**入库**候选 1 次嵌入 + 2 次 ctx.llm + 2–4 次 kNN（两路近邻查询）。

### 5.3 判分契约（judges.ts，全部 LLM 判定共用）

- **C-2 JSON 健壮解析**：剥 ```json 围栏 → 以文本中**最先出现**的 `{` 或 `[` 为起点（否则 `[{...}]` 会被误截成首个对象元素）截取首个平衡片段 → JSON.parse；失败抛错。
- **C-3 重试语义**：每次判定调用「调用+解析+结构校验」整体重试**一次**——校验失败（形状错误）与解析失败同样触发重试；两次均败才抛。
- M5 锚定示例（刷牙=2、约 crush=8、人生决策=10）写在系统提示词内；reasons 枚举过滤去重。
- 矛盾判定一次调用判定全部近邻（记录 + 节点 gist 混合清单），返回最强 verdict + index + **temporal**（仅 contradicts 有意义：'disjoint' 判定"不同时期、都真"，缺省/非法按 'overlapping' ——P0 安全网语义保持，宁软失效不错过取代）；index 越界/非法 verdict/unrelated → null（视为无矛盾直接入库）。

## 6. 检索管线（src/retrieval.ts、src/metrics.ts）

### 6.1 五阶段

```
q' = buildExpandedQuery(query, recentTurns, contextTurns)
  → L0：q' 嵌入一次，对检索宇宙（store.retrievable()：有效未压缩记录 + 有效节点，
        节点文本 = gist）精确 kNN，取 top l0TopK
        ——传了 at 时换用 retrievableAt(at)（时间旅行，§6.4）
  → CSLS：cue = 2·cos − r(q) − r(m)；r(q)=L0 池余弦均值，r(m)=item.r_m（节点 r_m 由第 7 步刷新）
          cold 记录/节点需 cue ≥ cueThreshold + coldCueBoost（唯一分层消费点）
          取 top cslsTopK
  → 精排：cross-encoder 对 csls 幸存文本批量打分（[0,1]，仅同查询内排序），取 top rerankTopK
  → MMR：λ·relevance − (1−λ)·max(与已选集的余弦)，relevance 缺失时以 cue 代理
  → top（默认 mmrTopK）+ suppressed（进过精排阶段但未进 top 者）
```

- 空宇宙直接返回空结果（不调嵌入/精排）；CSLS 后无幸存则不调精排端点。
- **C-5 精排失败降级**：rerank 端点异常不致命——沿用 cue 序进入 MMR（`relevance` 字段缺失），最终 score 投影按 `relevance ?? cue ?? cos` 取最好可用分。
- 消融档（设计 §7.1）：`base`/`csls`/`rerank` 提前返回对应阶段截断结果；`suppressed` 仅在 rerank/full 档有值。生产两通道恒用 `full`，消融档仅供 eval 脚本。
- 确定性：各级排序平局以 id 字典序决胜；MMR 同分取先遍历者。
- **ScoredCandidate 携带 `item: RetrievableItem`**（text/embedding/r_m/tier/createdAt/layer），下游（记账、工具输出、section 渲染）统一经 `item.layer` 区分情景层与语义层。

### 6.2 分层与门控

tier 只在两处被消费：cold 层的 cue 门槛（本节）与输出展示。记录 tier 落盘（写入时定型），节点 tier 由 `tierOf(node.S)` 在视图里现算。hot/warm 在行为上完全一致。`cueThreshold` (0.3) 只被 cold 门控消费。

### 6.3 expanded query 构造（buildExpandedQuery）

取 `recentTurns` 末尾 `contextTurns` 条、滤空后以 `\n---\n` 与 query 连接；`contextTurns <= 0` 时显式置空（规避 `slice(-0)` 取全数组的坑，源码有注释）。

### 6.4 时间旅行选项（P2，§2.5 完整版）

- `RetrieveOptions.at`（epoch ms）：L0 池换用 `lookup.retrievableAt?.(at)`（MemoryStore 实现）；lookup 未实现时退化为当前池（测试替身兼容）。后续各级（CSLS/精排/MMR/分层门控）与常规检索完全一致——时间只换池、不改排序权重（INV-1）。
- 唯一消费方：memory_search 的 `at` 参数（§9.2）；自动注入通道不使用时间旅行（每步注入永远面向"现在"）。

## 7. 睡眠巩固周期（src/sleep-cycle.ts，P1 交付、P2 增量）

设计 §2.3 七步的完整落地。**触发**在 runtime（§7.1），**批处理本体**在 sleep-cycle.ts，全部依赖注入（InternalLlm / EmbeddingProvider / 窄存储接口 `SleepStoreLike`），不依赖宿主框架，可离线单测。

### 7.1 触发门控（runtime.maybeSleep）

- 计数器 `newSinceSleep`：每次 `processTurn` 成功写入后累加 `written.length`；达到 `sleep.minNewMemories`（默认 10）即触发。
- 触发前检查：`sleep.enabled`、非 `sleeping`（**周期内不重入**）、聚类池（有效未压缩记录数）≥ `sleep.clusterMinSize`——池不足时**不清零计数**、等记忆继续累积。
- fire-and-forget：不阻塞回合；计数在运行前清零；`.finally` 中解除 `sleeping` 后**立即补判一次**（周期运行期间的新写入不丢失触发机会）。
- **不使用 `ctx.schedule` / `ctx.jobs`**：设计 §5.3 本就提供 turn/end 信号这一备选，README 已声明取舍（§2.1）。
- **P2 起**：S 兜底衰减随周期第 7 步执行（§7.7）——`sleep.enabled=false` 时离线维护（含全库衰减）整体停摆，事件路径的惰性衰减追补（§10.2）仍然生效。
- **B-8 失败语义细节**：计数在运行**前**清零——若周期整体抛错（已记日志），本轮累计的触发计数不回补，需再累计 `minNewMemories` 条新写入才重试。

### 7.2 确定性与常数（C-9）

- 聚类池与全库刷新都按 id 字典序遍历；连通分量、`maxNodeCos` 平局、簇排序均以 id 决胜——同库同配置结果可复现。
- **`M6_PROBES`**：|P| = 20 条多样化探针，设计 §3.6 固定值（如同 `RED_NEIGHBOR_TOP`），属度量工具常数、**不进 Config**。
- 节点 id 默认 `crypto.randomUUID()`，测试可注入 `newId`；`SleepStoreLike` 是 MemoryStore 的窄接口（`validMemories/validNodes/updateRecord/putNode/refreshNeighborhood/refreshNodeNeighborhood`）。

### 7.3 单簇流水（processCluster）

```
成员（按 id 序）
→ 第 2 步 gist 抽取（1 次 ctx.llm，{"gist": "..."}）→ gist 嵌入（1 次）
→ M6 epi 预计算（纯计算，见 7.5）
→ 第 3 步 QA 闸门：generateQaPairs（1 次，≤qaPairCount 对）→ 逐对 answerFromGist（各 1 次）
   → 平均 token 级 F1（qaF1，Han 单字 + 字母数字 token 多重集交叠）
   → 0 对 或 均值 < qaF1Threshold → 全簇标 incompressible，route='qa_failed'（簇保留）
→ 第 5 步 M6 闸门：gistEpi ≥ epiThreshold → 全簇标 incompressible，route='epi_failed'
   （摘要未去情景化，不可迁移；M6 前置于 M4 是有意排序：纯计算闸门先拦，
    可省一次 LLM 兼容复核调用，两闸都过才迁移、语义等价）
→ 第 4 步 M4 路由 + 第 6 步迁移：
   · 语义网络为空 → 无条件建首节点（引导路径；设计未定义空网情形，P1 政策）
   · con = z( gist 对网络峰值余弦 )，基线 = 最近 conWindow 条未压缩记录的峰值余弦分布
     （σ 下限 1e-9 防 0 除；基线空 → con=0 → 留情景层）
   · con > conAttachSigma → LLM 兼容复核（1 次）：通过 → 挂入（member_refs 追加、
     节点 S += attachGain）+ 成员压缩（归档时点 compressed_at 见 §7.6）；不通过 → stayed
   · con < conNewNodeSigma 且簇均 imp ≥ conNewNodeMinImp → 建新节点（S = 簇均 imp）
   · 其余 → stayed（等下个巩固周期）
失败语义：单簇失败不中断整轮（记日志继续）；signal 中止则原样上抛。
```

### 7.4 闸门拒收语义（C-10）

`qa_failed` / `epi_failed` 都不是错误：簇保持原状继续可检索，全簇成员标 `flags.incompressible`。聚类阶段要求分量内**至少一名成员未标记**——全簇已标 = 上轮闸门已拒，需新成员加入才值得重试（防止对同一簇反复烧 LLM）。

### 7.5 M6 完整 epi（gistEpiScore）

`σ( z(实体密度) + z(时间表达密度) − z(G) )`，系数 a=b=c=1（设计固定）。三个特征都相对「当前有效未压缩情景记忆」分布做 z 标准化（`zScore` 带 σ 下限、空分布返 0）；G = 对 20 探针的平均余弦。z 化是刻意的：裸余弦跨嵌入模型不稳定，z 化后 `epiThreshold` 才有尺度不变的含义。写入路径记录上的 `epi` 仍是词法近似（§3.1）——完整公式只作用于 gist。

### 7.6 迁移与归档

- 建新节点：`putNode`（S=簇均 imp、r_m=0 待第 7 步刷新）→ 成员逐条 `updateRecord`：`flags.compressed_into = nodeId`、`flags.qa_passed = true`、`time_meta.compressed_at = 归档时点`（P2，时间旅行视图消费）、`con_route` 定型（INV-6）。
- 挂入已有节点：`putNode({...attachTo, member_refs: 追加, S: +attachGain})` → 成员同上，`con_route = attached`。

### 7.7 第 7 步：全库统计刷新与 S 兜底衰减（P2）

即使本轮无簇也执行：

- **邻域刷新**：对全部有效未压缩记录刷新 r_m/red，对全部有效节点刷新 r_m——新写入在周期之间漂移的邻域统计由此收敛（§4.5、B-2）。代价：每周期对全库做 O(n·kNN) 精确检索。
- **S 兜底衰减**（scoring.ts 纯函数 `applyDecay` / `applyNodeDecay`，§10.3）：对同一集合（留层记录 + 有效节点）按 `S·e^(−Δt/τ)` 衰减并前移 `counters.last_decay_at`、重算 tier。只作用于仍在检索宇宙者（软失效与已压缩归档的 S 是惰性值，不参与分层）；**衰减引起的层级跃迁不触发 M5 重判**（§10.4）。结果计入 `SleepOutcome.decayedRecords / decayedNodes` 并进 runtime 日志行。

## 8. 自动注入通道内部（runtime.observeAgents + renderAutoSection）

### 8.1 生命周期

- `config.section.enabled === false` 时整条通道不注册（连 pendingQuery 监听一起省略）。
- 每个 `agent/created`：在该 agent 的**定域 context** 上注册 `system-prompt/assemble` waterfall 监听器——定域注册使监听器只收该 agent 的装配、且随 agent dispose 自动逆序清理（宿主契约）。依赖升 0.2.1-rc.2 后该事件为 **serial**：监听器按序 await、返回值须为 `undefined | Promise<undefined>`，本插件监听器为 async（src/runtime.ts）。
- **HMR 卸载契约（bugfix）**：`agent.ctx` 上的 effect 只随 agent 卸载、**不随插件卸载**（cordis：effect 登记在接收方 fiber）。旧实例的 assemble 监听器若在重载后存活，会经已 closeAll 的 ScopeRegistry 重开刚关掉的 unit，新实例再开即撞宿主 `already-open` 保护（该工作区直到重启宿主都不可用）。对策（src/runtime.ts observeAgents）：每个监听器的 disposer 显式登记，插件卸载时全部摘除（该 effect 注册晚于 closeAll effect，fiber LIFO 反注册保证先摘监听器、后关 unit）；启动时经 `ctx.agents.list()` 对重载前存活的 agent 补挂（存量 agent 不会再收到 `agent/created`）；ScopeRegistry closeAll 后进入终态，迟到 get 一律拒绝、绝不重开。
- `agent/inbox/claimed`（全局监听，按 source.kind==='user' 过滤）：记录每 agent 最新待处理人类输入 → `pendingQuery`；`agent/disposed` 时清除（并同步清理监听器登记）。
- **B-3 宿主边界**：若该 agent 作用域内有**complete section** 注册（如 agent preset 遮蔽），waterfall 返回后宿主会恢复 complete section 为唯一提示词——本插件 push 的记忆 section 会被**静默丢弃**。这是宿主明文契约（dsh-system-prompt index.d.ts assemble 事件注释），插件无对策，属于部署组合的固有权衡。

### 8.2 查询来源优先级

`pendingQuery.get(agentId)`（本轮 claimed 的最新人类输入）→ 回退到 `recent` 中最近一条 user 消息 → 两者皆无则返回空串（不注入）。

### 8.3 装配期行为

```
listener(assembly, context, next):
  downstream = await next()          // 必须先放行（不拦截流水线）
  try:
    text = renderAutoSection(agentId, context.signal)   // 信号只作用于本次装配
    if text: downstream.sections.push({ name:'dsh-mem', text })
  catch: log 后放行原样 downstream   // 检索失败静默，绝不破坏装配
  return downstream
```

### 8.4 同轮缓存与记账

- **C-7 缓存键 = expanded query 字符串**：同轮内后续 step（工具调用后重新装配）展开查询不变 → 复用 `lastResult`，不重复调用嵌入/重排端点、**不重复记账**；查询或 recent 变化 → 重跑全链。
- 每次全新检索触发一次 `ScoreKeeper.recordRetrieval`（fire-and-forget，P2 起取代 P0 的 recordUse）：top（情景记录 + 语义节点）= 使用事件、suppressed = 抑制事件——S 动态（增益/惩罚/惰性衰减追补/tier 跃迁/跃迁重判）全在 scoring.ts（§10）。目标已被软失效时静默跳过。
- 通道不使用 `exec.agent.inject` / `agent.inject()`——自动上下文按设计走 section，不走 inject 通道。
- section 渲染（`formatMemories`）：语义层命中追加 ` type=gist` 标记，模型可区分原始记忆与蒸馏 gist。

## 9. memory_search 工具内部（src/tool.ts）

### 9.1 注册与开关

`config.tool.enabled` 控制；与 section 通道互相独立（两者都关时插件仍写入记忆并运行睡眠周期）。

### 9.2 规范输出（SearchOutput）

```
{ query, expandedQuery,
  memories: [{ id, text, score, cue?, tier('hot'|'warm'|'cold'),
               layer('episodic'|'semantic'), createdAt }],
  suppressedCount,
  at?,     // 时间旅行时点（epoch ms），仅调用方传了合法 at 时出现
  error? } // 领域性不良输入（at 无法解析 / limit < 1），此时 memories 为空
```

- `output.schema` 显式 `additionalProperties:false`（对象节点硬性要求）；`score = relevance ?? cue ?? cos`（最好可用分）；`layer` 区分原始记忆与睡眠周期蒸馏的 gist。
- **参数**：`query`（必填）；`limit`（integer，≥1 在 execute 内领域级校验——参数 DSL 不支持数值边界，见 F-11）；`at`（string：纯数字按 epoch ms，其余须为以 4 位年份开头的 ISO 8601——Date.parse 对杂串过于宽容，`-5` 也能解析出正时间戳；非正时点拒绝，记忆库不存在 1970 前数据）。
- `render` 是规范值的**纯投影**：error → 失败文本；空数组 → 'No relevant memories found.'；编号行，语义层追加 ` gist` 标记。UI 格式不进规范值。
- `presentCall` 返回 `generic` 卡（kind 'search'）、`presentResult` 返回 `generic` 卡——均为纯函数。
- `limit` 覆盖默认 `tool.maxResults` 直接作为 `topK`；`at` 经 `parseAt` 解析后作为检索 `at` 选项（§6.4）。
- `execute` 全程携带 `exec.signal`；`exec.agent` 只读（取 recentTurns），不调用 inject。

### 9.3 记账

每次 execute 触发 `onRetrieved`（即 `ScoreKeeper.recordRetrieval`，语义同 §8.4）——工具路径与自动路径的记账规则一致，但互不复用缓存（各自独立检索）。

### 9.4 memory_clear 工具（开发/测试用，默认关）

`config.tool.clear`（默认 **false**）控制注册，与 `tool.enabled` 互相独立；定位是测试迭代时快速清空当前工作区记忆库，不是产品功能：

- **INV-2 的唯一例外**：`MemoryStore.clearAll()`（§4.4）对双表逐键 `deleteRecord` **硬删除**——含软失效与已压缩归档记录，时间旅行（`at`）亦不可回溯；只清当前作用域（M2 隔离边界内，跨工作区不可达，全清请删库文件）。清空同时复位该作用域的 `newSinceSleep`（避免残留计数在下一轮 turn/end 触发一次空池睡眠周期）。
- **双闸**：配置闸（`tool.clear`）+ 参数闸——`confirm` 必填且必须**严格为 true**：缺失由 `defineTool` 宿主参数校验抛 `ToolArgsError`（execute 不触达）；`false` 在 execute 内写规范 error 值（不抛异常、不触碰存储，工具契约与 §9.2 的 `at`/`limit` 同路径）。
- 规范输出 `{ episodic, semantic, total, error? }`（删除计数）；`render` 纯投影（error → `memory_clear refused: …`，成功 → `Cleared N …`）；`presentCall` generic 卡 kind `'delete'`。
- 设计语义下记忆应经矛盾软失效与睡眠压缩自然消退，生产 profile 保持默认关闭；日常清库（换嵌入模型、version 迁移等）仍以删介质文件为准（README 排障）。

## 10. 评分引擎（src/scoring.ts，P2 支柱一 S 完整动态）

设计 §2.1 的完整落地。纯函数 + ScoreKeeper 编排，依赖注入（InternalLlm / 窄存储接口 `ScoreStoreLike`：get/updateRecord/getNode/putNode），不依赖宿主框架，可离线单测。

### 10.1 事件语义（§2.1）

```
初始：    S ← imp                                  （写入路径，P0）
成功使用：S ← S + α·(1 + cue)·g(arousal)           α = score.useGain (0.5)
                                                  g = 0.5 + 0.5·arousal ∈ [0.5,1]（§3.5 乘法门；节点无 arousal，门恒 1）
被抑制：  S ← S − ε                                ε = score.suppressPenalty (0.05)，每查询至多一次
兜底衰减：S ← S·e^(−Δt/τ)                          τ = score.decayTauDays (180 天，半衰期 ≈ 125 天)
```

- **「成功使用」= 进入最终上下文**（两条检索通道的 top 输出，`recordRetrieval` 统一入口）。设计 §2.1 的「被采纳」（ctx.messageFeedback）不在依赖集内（该包已发布 npm，纳入评估见仓库 TODO.md）：按「未被纠正」默认即时入账（P1 对 ctx.schedule 的同款取舍，§2.1 未接入行）；接入后可改为确认制——改造点集中在 recordRetrieval 的入账时机。
- **(1 + cue) 下夹 0**：cue < −1 的"使用"不产生负巩固（§2.1 公式直取会出现负增量，非设计意图）。cue 缺省回退 last_cue_quality，再缺省 0。
- **抑制只记弱形式**（§2.2）：落选计数 + ε 惩罚，不做持久性强抑制扣分（Murayama 2014，设计 §8 弃用项）。

### 10.2 惰性兜底衰减（INV-7）

锚点 = `counters.last_decay_at`（缺省 `created_at`，旧记录容忍不回填）。事件路径（使用/抑制）先补齐自锚点以来的衰减再加/减增量、锚点前移到事件时刻；批处理路径（睡眠周期第 7 步）对全库衰减。指数衰减可乘复合 → 与「逐日衰减 + 事件增量」数学等价，无需任何定时器。elapsed ≤ 0（同刻/时钟回拨）因子为 1（幂等）。

### 10.3 批处理衰减（睡眠周期第 7 步，§7.7）

`applyDecay` / `applyNodeDecay` 纯函数由 SleepCycle 调用（本模块不持有定时触发）；作用域 = 有效未压缩记录 + 有效节点（其余记录的 S 是惰性值）。

### 10.4 层级跃迁与 M5 重判（§3.5）

- tier = tierOf(S) 随任何 S 变更重算（记录落盘字段；节点视图现算）。
- **事件驱动的跃迁**（使用/抑制路径）触发 M5 重判：`judgeImportance` 重跑一次，新判分按 EMA（`score.rejudgeEma` 为新值权重）混入 imp/valence/arousal（reasons 取新值）。重判失败保留旧值、记日志不抛（增强信号不阻塞记账链）。
- **衰减引起的跃迁不重判**：衰减是工程保险、不构成重要性的新证据；同时防 S 在阈值附近被"使用推上/衰减漂下"反复穿越导致重判风暴。此为对设计「只在层级跃迁时重判」的工程化收窄，README/本文为权威记录。
- 节点跃迁不重判（无 M5 字段）。

### 10.5 确定性与容错

- 每事件独立 try/catch：记录缺失/节点缺失/更新失败 → 记日志跳过，绝不上抛（fire-and-forget 链）。
- 软失效目标静默跳过（检索与记账之间可能被推翻）；S 动态只作用于有效记忆。

## 11. 内部 LLM 调用（src/llm.ts，CordisLlm）

- **C-8 终态判定契约**：`ctx.llm` 契约下适配器/提供方失败被规范化为**终态 error/aborted finish 块**，迭代本身不抛错——必须经 `assembler.finish` 读取后显式抛错（携带 code/status），否则真实失败会被误报为空回复。空回复同样按失败抛。
- 每次调用构造独立的 `createUserMessage`（source kind 'user'）+ `system` 文本；`provider/model/temperature/maxTokens` 全部来自 Config；`signal` 存在时透传。
- `config.llm.provider` 必须是宿主 ctx.llm 上**已注册适配器的路由名**（如 `deepseek`）；凭据由宿主适配器解析，插件不接触 key。
- **P2 起消费方共 8 类**：候选抽取、M5 判分、矛盾判定（写入管线）；gist 抽取、QA 对生成、gist 作答、M4 兼容复核（睡眠周期）；层级跃迁 M5 重判（评分引擎）。P2 起三条内部链路（写入管线/睡眠周期/评分引擎）共用一个 `CordisLlm` 实例（无调用间状态，同一 Config 路由）。不设置 `purpose` 字段。

## 12. 嵌入/重排客户端（src/embedding.ts）

dsh 无嵌入/rerank seam（ref capability-seams 全表核实）——二者是**插件自有 HTTP 依赖**，端点/模型/维度全在 Config。

- **协议**：`/embeddings` OpenAI 兼容（`{model, input[]}`，按返回 `index` 对齐、缺口/数量不符即报错）；`/rerank` Cohere/Jina 式（`{model, query, documents, top_n}`，读 `results[].relevance_score`，量纲处理见下条）。
- **重排量纲自适应（本地 llama.cpp 兼容）**：llama.cpp 的 `/v1/rerank` 直接返回模型原始输出（logit，server 侧无 sigmoid），云端服务（SiliconFlow/Jina）返回的则是已归一 [0,1] 分数。客户端按**整组一致**判定量纲：本次响应中任一分数越出 [0,1] 即整组视为 logit、经 `sigmoid` 归一，否则视为已归一原样使用；两种量纲最终都夹取 [0,1]（与 C-6 同一立场：不信任服务端量纲）。README「推荐：本地部署 llama.cpp」一节是官方推荐的端点部署方式——**llama.cpp 与宿主进程无关联**：两个 server 须用独立脚本先于宿主拉起并探活（README 部署节第 6 步），宿主运行中掉线可在其恢复后自愈。
- **C-6 归一化职责**：http 模式在客户端本地归一化（不信任服务端单位长度）；deterministic 替身同样归一化。所有下游（索引、余弦、MMR 相似度、M6 探针相关度）依赖此契约。
- **超时合并**：`AbortSignal.any([caller.signal, AbortSignal.timeout(timeoutMs)])`。
- **deterministic 模式**：FNV-1a 词袋哈希双桶嵌入 + 余弦式 rerank 替身——同文本同向量、只验证管线连通性，**数值无语义意义**（README 与三个 eval 输出均已声明）。
- **P1 新增消费**：gist 嵌入、M6 探针集嵌入（每周期一次、仅当有簇）。

## 14. 生命周期与并发

**启动序列（M2 起）**：`apply` → `MemoryRuntime.start()`（异步、失败仅记日志不杀宿主）→ 验证 storage 后端可用（backend.get + kv facet 检查；**unit 不在启动期打开**）→ 建 embedding/reranker/CordisLlm（跨作用域共享、无调用间状态）→ 建 ScopeRegistry（`ctx.effect` 注册 closeAll）→ 注册 session 观察、agent 观察、（tool.enabled 时）memory_search、（tool.clear 时）memory_clear（§9.4）→ 打印 `started: backend=…, workspaceScope=…, clearTool=…`。unit 随首个作用域命中惰性打开（写入 turn/end、检索装配/工具），每开一个作用域记一行 `scope opened: unit=… (N valid memories)`。

**重载**：插件卸载（HMR 或依赖消失）→ 全部 effect 逆序清理（事件监听、工具注册、ScopeRegistry.closeAll 关闭全部 unit——含在途 open 完成后）。睡眠周期与记账链无独立注册——它们只是运行中的 Promise，重载后新实例以介质现状重建（周期内未完成的写入已按 INV-4 逐条落盘）。

**进程内状态**：
- `sessions: Map<sessionId, {recent, pending, watermark, scopeKey?, lastExpandedQuery?, lastResult?}>`——**B-4 无上限**：不随会话销毁清理（agent/disposed 只清 pendingQuery）；每会话留存一个滑动窗口，常驻宿主下缓慢累积。
- `pendingQuery: Map<agentId, text>`——随 agent 生命周期清理。
- `scopes: ScopeRegistry<ScopedRuntime>`——作用域单例表（含每作用域 `newSinceSleep` + `sleeping` 门控，§7.1 的计数/重入语义不变、粒度变为每工作区）。

**并发写链全景**（C-1c）：写入管线（每 turn/end）× S 记账 `recordRetrieval`（每检索，含跃迁时的 M5 重判 LLM 调用）× 睡眠周期（门控，含第 7 步衰减写）——三条 fire-and-forget 链，跨链同记录并发 `updateRecord` 的丢失更新窗口已被所有者接受（README 取舍段：最坏一次 flag/计数/S 增量，下一周期自愈）。
