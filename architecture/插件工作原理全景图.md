## 1. 全景图

```text
┌─ dsh 宿主（契约一律见 ref/，本文不复述）────────────────────────────────────────
│  [日志] 会话日志 session/event：持久事件 user/message / assistant/message / turn/end
│  [循环] Agent 实时事件：agent/created / agent/inbox/claimed / agent/disposed
│  [装配] system-prompt/assemble waterfall：每步系统提示词装配（agent 定域分发）
│  [工具] ctx.tools：defineTool 注册表（exec.signal / 规范 JSON 输出）
│  [模型] ctx.llm：provider 无关流服务（适配器失败收敛为终态 error/aborted finish 块）
│  [存储] ctx.storage：后端注册表 + KvUnit（单次写原子且持久；并发写顺序由调用方负责）
└───────────────────────────────────────────────────────────────────────────────
        │
        │ 持久事件 = 记忆的唯一来源（[日志]）；[循环] 提供定域生命周期与查询提示
        ▼
┌─ dsh-mem 插件 ────────────────────────────────────────────────────────────────
│  (1) 观察层 observeSessions / observeAgents（src/runtime.ts）
│        │  pending / recent 双缓冲；turn/end 取走本轮批次，fire-and-forget 进入写入
│        ▼
│  (2) 写入管线 write-path + judges（src/write-path.ts）
│        │  候选抽取、M5 判分、矛盾判定 ──▶ [模型] ctx.llm
│        │  幸存候选批量嵌入 ──▶ (E) 外部端点 /embeddings
│        │  写入结果累计 newSinceSleep 计数 ──▶ (6) 触发门控
│        ▼
│  (3) 记忆库 memory-store + vector-store（src/memory-store.ts）
│        │  putRecord / putNode / softInvalidate / refresh* ──▶ [存储] KvUnit
│        │  检索宇宙 = 有效未压缩记录 + 有效节点（INV-3）
│        ▼
│  (4) 检索管线 retrieval + metrics（src/retrieval.ts）
│        │  L0 余弦召回 → CSLS → cross-encoder 精排 → MMR
│        │  查询向量与精排 ──▶ (E) 外部端点 /embeddings 与 /rerank
│        ├──▶ (5a) 自动注入通道：agent 定域 assemble 监听 ──▶ [装配] push 'dsh-mem'
│        └──▶ (5b) 主动召回通道：memory_search 工具 ──▶ [工具] ctx.tools
│
│  (6) 睡眠巩固周期 sleep-cycle + judges（src/sleep-cycle.ts；turn/end 门控触发）
│        │  聚类 → gist 抽取 / QA 生成 / gist 作答 / 兼容复核 ──▶ [模型] ctx.llm
│        │  gist 与探针嵌入 ──▶ (E) /embeddings；建/挂节点与压缩归档 ──▶ (3)
│        │  第 7 步全库邻域刷新（无簇也执行）
│
│  (E) 插件自有外部端点（dsh 无此 seam，插件自有依赖）：
│      /embeddings（OpenAI 兼容）与 /rerank（Cohere/Jina 式）；embedding.ts 客户端，
│      deterministic 模式为离线替身（只验证管线连通，数值无语义意义）
└───────────────────────────────────────────────────────────────────────────────
```

数据只有一个入口（会话日志事件 → 写入管线）、两个模型可见出口（自动注入 section、memory_search 工具）和一条离线支路（睡眠周期 → 语义层迁移）。时间戳不参与检索排序、衰减或删除（INV-1 的精确边界见 §3.3）。

### 2.2 通道选择依据（与设计的差异记录）

设计 §5.0 首选 `ctx.systemPrompt.section()` 作为自动通道。实现改用 **`system-prompt/assemble` waterfall（agent 定域）**，原因：`PromptSection.text` 的 provider 签名是**同步**的（`string | ((context) => string)`，见 `@deepseek-ai/dsh-system-prompt/lib/types/index.d.ts`），承载不了异步检索链路。`system-prompt/assemble` 整体装配变换是 ref 官方文档同章节列出的扩展点（extension-cookbook：「系统提示词可配置性」行及 assemble 专段），且功能→机制映射的「记忆」行由 section 提供方 + 工具两条通道共同满足——本插件的 waterfall 监听器就是该 section 的异步等价物。此差异已在 README「实现选择说明」声明，此处为唯一权威记录。

## 3. 数据模型（实现层）

定义在 `src/types.ts`；此处记录**实现语义**（与设计 §4 的差异以本文为准）。

### 3.1 MemoryRecord（episodic 表）

| 字段 | 类型 | P0+P1 实现语义 |
|---|---|---|
| `id` | UUID v4 | 不可变（C-4）；`crypto.randomUUID()` 生成 |
| `text` | string | 自包含第三人称陈述；写入前对库内 valid 记录查重（§5.3） |
| `embedding` | number[] | L2 归一化后落库（C-6）；维度 = `config.embedding.dimensions` |
| `imp` / `valence` / `arousal` | number | M5 判分输出，经夹取（imp 1–10 整数、valence −1..1、arousal 0..1） |
| `epi` | number [0,1] | 写入时 = **词法近似**（实体+时间表达密度 sigmoid 合成，`epiLexical`）；睡眠周期的完整 M6 公式（z 化 + G 探针）只用于 gist（§7.5），不回写成员 |
| `r_m` / `red` | number | 邻域统计；`r_m` = 检索宇宙 top-`retrieval.cslsK` 近邻平均余弦，`red` = top-5 近邻平均余弦（§4.5）；写入时算新记录自身，全库刷新由睡眠周期第 7 步承担（B-2） |
| `tier` | hot/warm/cold | 由 S 与 `tier.hotThreshold/coldThreshold` 派生（`tierOf`）；检索时的唯一分层消费是 cold 门控（§6.2） |
| `con_route` | attached / new_node / pending | P0 恒为 pending；**P1 起由睡眠周期迁移步骤写入**（new_node → `{kind:'new_node',nodeId}`，attached → `{kind:'attached',nodeIds:[nodeId]}`） |
| `links` | MemoryLink[] | `supersedes`（矛盾时指向被软失效者）/ `complements`（补充时指向被补充者）；`related` 尚无生产方 |
| `S` | number | 记录 S 仍恒为 `imp` 初始化、无更新路径（完整动态 P2）；节点的 S 有 P1 部分动态（§3.2） |
| `counters` | used_count / suppressed_count / last_used_at? / last_cue_quality? | 使用记账落位（§8.4/§9.3），P2 的 S 动态消费；**仅情景层记账**——语义节点无 counters，命中节点不计数（P2 补） |
| `time_meta` | created_at / valid_at / invalid_at? | 纯元数据（INV-1）；`invalid_at` 是唯一的失效标记 |
| `flags` | superseded_by? / compressed_into? / qa_passed? / **incompressible?** | P1 新增 `incompressible`：QA/epi 闸门拒收标记，全簇标记后需新成员加入才重试（§7.4）；`compressed_into` + `qa_passed` 由迁移写入（§7.6） |
| `origin` | {session_id, turn, seq} | 溯源审计用，可选 |

### 3.2 SemanticNode（semantic 表，P1 起填充）

| 字段 | P1 实现语义 |
|---|---|
| `id` / `gist` / `embedding` | UUID；LLM 蒸馏的自包含摘要（§7.3）；归一化向量（C-6） |
| `epi` | gist 的**完整 M6 epi**（z 词法特征 − z(G 探针)），迁移闸门输入 |
| `links` / `member_refs` | P1 无 links 生产方；`member_refs` = 被压缩归档的成员记录 id（迁移时写入，挂入时追加） |
| `S` | 新建 = 簇均 `imp`（与记录「S 初始化为 imp」同构）；被挂入时 `S += sleep.attachGain`（设计 §2.1 α=0.5 的沿用）；完整动态 P2 |
| `r_m` | 与检索宇宙 top-k 近邻的平均余弦，第 7 步刷新（新建时置 0 后统一刷新） |
| `time_meta` | 同记录语义；**B-6 节点软失效无生产方**：矛盾判定只针对 episodic 记录（`similar()` 只返回记录），gist 被新记忆推翻时节点仍留在检索宇宙——支柱五对语义层的完整覆盖在 P2（README「明确不在 P1」已声明） |
| tier（派生） | 不落盘：`retrievable()` 视图按 `tierOf(node.S)` 现算 |

### 3.3 数据不变量（全库强制）

- **INV-1 时间中立（精确边界）**：时间戳永不作为检索排序、衰减或删除的输入。唯一例外是**非决策性采样**——M4 con 基线窗口按 `created_at` 取最近 `sleep.conWindow` 条（设计 §3.4 固定的「滚动分布」定义，产出的是统计基线而非记忆排序）。设计 §2.4 的「查询含时间意图时启用 recency 特征」仍未实现。
- **INV-2 只软失效不删除**：失效 = 设 `time_meta.invalid_at` + `flags.superseded_by` 并移出索引；记录与介质行永存。语义节点同款双时间戳语义（P1 无失效生产方，B-6）。
- **INV-3 索引与检索宇宙双层视图**：VectorIndex 含**全部有效 episodic 记录（含已压缩归档者）+ 全部有效语义节点**；消费侧两个过滤视图——`similar()`（写入路径矛盾判定）= 有效记录**含已压缩**（归档记忆仍可被新信息软失效，P0 安全网不因 P1 迁移退化）；`retrievable()`/`searchRetrievable()`（检索宇宙）= 有效**未压缩**记录 + 有效节点。软失效项在两个视图中都被排除。
- **INV-4 先持久化后镜像**：任何写操作先 `await unit.putRecord(...)` 成功，再更新内存 Map 与索引（记录与节点同规）；镜像与介质不会出现「镜像有、介质无」。
- **INV-5 嵌入归一化**：落库与入索引前都经 L2 归一化（`embedding.ts` 服务端归一 + `vector-store.ts` 入索引再归一，双保险）；余弦因此等价于点积。记录、节点 gist、M6 探针向量同规。
- **INV-6 压缩归档语义**：`compressed_into` 指向承接 gist 的节点；成员记录退出检索宇宙但保留在存储与 `similar()` 视图中（INV-3），回溯经该 flag 索引原记录。QA/epi 闸门拒收 → 全簇 `incompressible: true`，**拒收不是失败**：簇保留原状，需新成员加入（聚类池要求至少一名未标记成员）才会重试。

## 4. 存储层（src/memory-store.ts、src/vector-store.ts）

### 4.1 KV unit 形状

```
descriptor = { name: config.storage.unit (默认 'dsh-mem', 匹配 /^[a-z][a-z0-9_-]*$/),
               version: config.storage.version (默认 1),
               tables: ['episodic', 'semantic'], hasGlobal: false }
```

- 表→记录：episodic 存 MemoryRecord、semantic 存 SemanticNode，键 = 记录/节点 id，**无 global 槽**。
- 版本契约：开库时介质版本 ≠ descriptor.version → 宿主抛 `version-mismatch`（宿主契约）。P1 只向记录/节点新增可选字段（旧记录缺字段按 undefined 容忍），**version 保持 1 即可**；真正不兼容的变更（含更换嵌入模型/维度）仍须 bump version 或清空旧 unit（B-5）。

### 4.2 内存镜像与索引

`MemoryStore.open()` 全量 `loadAll()` 后逐表最小形状校验（记录：id/text string + embedding number[]；节点：id/gist string + embedding number[]；不合规跳过并 warn 一次，不抛错），重建两个 Map 与索引（按 INV-3 的全集口径：valid 记录含压缩者 + valid 节点）。

### 4.3 并发模型（内部契约 C-1，必读）

宿主 KvUnit 契约明确：**单次调用原子且 resolve 即持久，但不串行化并发写——写顺序由调用方负责**（`dsh-storage` backend.d.ts）。插件据此确立：

- **C-1a 镜像读改写在前、await 在后**：`updateRecord` 的「读镜像 → fn → 计算新值」全部同步完成于首个 await 之前，单条 JS 任务内不会交错。
- **C-1b 单管线内串行**：写入管线对候选逐条 await；睡眠周期对簇逐个、对成员逐条 await；`softInvalidate` 幂等。
- **C-1c 跨链竞争（所有者已接受的取舍）**：进程内现有**三条**独立 fire-and-forget 写链——写入管线（每 turn/end）、使用记账 `recordUse`（两条检索通道触发）、睡眠周期（门控触发）。跨链对同一记录并发 `updateRecord` 存在丢失更新窗口；最坏损失是一次 flag/计数增量，可被下一周期自愈。该取舍由 README「已知接受的取舍（P1）」段声明为准；P2 消费计数器前若需精确，应为 MemoryStore 增加每记录写链（对齐 storage-domain 的单链纪律）。

### 4.4 双视图查询接口

| 接口 | 视图 | 消费方 |
|---|---|---|
| `similar(vector, k)` | 有效 episodic 记录（**含已压缩**），经索引 filter + 镜像复核 | 写入路径矛盾判定（§5.2）；这就是压缩记忆仍可被推翻的安全网 |
| `retrievable()` / `searchRetrievable()` | **检索宇宙**：有效未压缩记录 + 有效节点（节点 tier 由 S 现算） | 检索管线 L0（§6.1）、邻域统计（§4.5）、聚类池与 con 基线（§7） |
| `validMemories()` / `validNodes()` | 全部有效记录/节点（不过滤压缩） | 睡眠周期聚类池（自行再滤 compressed）、启动日志计数 |

### 4.5 邻域统计 `refreshNeighborhood(id,k)` / `refreshNodeNeighborhood(id,k)`

- 近邻取自**检索宇宙**（§4.4），即 r_m/red 所服务的 CSLS/聚类视图；
- 取 `max(k,5)+1` 个近邻（+1 容纳自身），**排除自身**后截断；
- `r_m` = 前 k 个近邻平均余弦（不足取实际数），`red` = top-5 平均余弦；
- 5 是设计 §3.3 公式的固定宽度，**非可调参数**（源码常量 `RED_NEIGHBOR_TOP`）；
- 结果写回并持久化。**B-2 周期间漂移窗口**：写入路径只刷新新记录自身；全库（含节点 r_m）刷新由睡眠周期第 7 步承担（§7.7）——两次周期之间，既有记录的 r_m/red 随新写入逐渐失真，检索侧消费的是最近一次刷新的快照。

### 4.6 向量索引（vector-store.ts）

精确 kNN 暴力扫全量（P0 规模选择；`VectorIndex` 接口为 ANN 预留；睡眠聚类是 O(n²) pairwise，同规模假设）。同步签名是有意契约；平局以 id 字典序决胜，保证可复现。`putRecord`/`putNode`/`updateRecord`/`softInvalidate` 都经 `syncIndex` 的 remove-then-conditionally-add 语义维护索引。

## 5. 写入管线（src/write-path.ts、src/judges.ts）

*P1 未改动本管线（write-path.ts 与 llm.ts、embedding.ts 同为 15:46 版本）；变化仅在其调用方：每轮写入结果 `written.length` 累计进 `newSinceSleep` 触发计数（§7.1）。*

### 5.1 触发与批处理（runtime.observeSessions）

```
session/event(user/message, source.kind==='user') ──┐
session/event(assistant/message) ───────────────────┤→ pending[] + recent[] 双缓冲
session/event(turn/end) → 取走 pending 批次 → fire-and-forget processTurn
                                            └→ 完成后累计触发计数 → maybeSleep()
```

- 只有人类输入（source.kind === 'user'）与全部 assistant 消息进入缓冲；agent.inject() 合成上下文、goal 轮次被 source 过滤排除。
- `recent` 上限 = `write.messageWindow × 2` 条（滑动窗口），供查询扩展与工具侧 recentTurns 消费；`watermark` 已记录但目前无消费方（B-7）。
- **turn/end 处理是 fire-and-forget**：写入永不阻塞回合计时；失败仅记日志。
- 事件数据形状（经 dsh-session 类型确认）：`user/message` 的 data 即 UserMessage；`assistant/message` 的 data 为 `{turn, step, message, usage?}`（取 `.message`）；`turn/end` 的 data 为 `{turn, reason}`（取 `.turn`）。

### 5.2 每轮七步（WritePipeline.processTurn）

对窗口内消息（最多 `write.messageWindow` 条）：

1. **候选抽取**：1 次 ctx.llm 调用，返回 ≤ `write.maxCandidates` 条自包含陈述（非数组即重试）。
2. **去重**：对库内 **valid** 记录文本集合 + 本批已见集合做精确匹配去重（被软失效的同文记录不阻止重写）。
3. **嵌入**：全部幸存候选**一次批量**调用（`embedding.batchSize` 分片）。
4. **逐候选串行**，每条：
   a. M5 rubric 判分（1 次 ctx.llm）→ `imp < write.minImportance` 则 dropped；
   b. 近邻查询（同步 kNN，`write.contradictionTopK` 个且 cos ≥ `write.contradictionMinCos` 的 valid 记忆，**含已压缩归档者**——§4.4 安全网）→ 矛盾判定（1 次 ctx.llm）；
   c. verdict 分派：`duplicate` → dropped（NOOP）；`contradicts` → 对旧记录 `softInvalidate` + 新记录建 `supersedes` 边；`complements` → 建 `complements` 边；`unrelated`/无近邻 → 直接入库；
   d. `putRecord`（S=imp 初始化、tier 定型）→ `refreshNeighborhood`。
5. **失败语义**：单候选任何一步失败 → dropped+1、记日志、**不中断整轮**；`signal` 已中止则原样上抛。

成本口径（对齐设计 §5.4）：每轮 1 次抽取调用 + 每条**入库**候选 1 次嵌入 + 2 次 ctx.llm + 2 次 kNN。

### 5.3 判分契约（judges.ts，全部 LLM 判定共用）

- **C-2 JSON 健壮解析**：剥 ```json 围栏 → 以文本中**最先出现**的 `{` 或 `[` 为起点（否则 `[{...}]` 会被误截成首个对象元素）截取首个平衡片段 → JSON.parse；失败抛错。
- **C-3 重试语义**：每次判定调用「调用+解析+结构校验」整体重试**一次**——校验失败（形状错误）与解析失败同样触发重试；两次均败才抛。
- M5 锚定示例（刷牙=2、约 crush=8、人生决策=10）写在系统提示词内；reasons 枚举过滤去重。
- 矛盾判定一次调用判定全部近邻，返回最强 verdict + index；index 越界/非法 verdict/unrelated → null（视为无矛盾直接入库）。

### 5.4 与设计的偏差

| 设计条款 | 实现状态 | 去向 |
|---|---|---|
| §5.1 第 6 步 con 路由（写入时） | 记录 con_route 恒 pending，路由移入睡眠周期（按簇批量做，设计 §2.3 原义） | §7.6 |
| §3.5「层级跃迁时重判 / EMA」 | 无重判（S 无更新路径） | P2 |
| §5.0 messageFeedback「被采纳」信号 | 未接入；counters 已落位 | P2 |

## 6. 检索管线（src/retrieval.ts、src/metrics.ts）

### 6.1 五阶段

```
q' = buildExpandedQuery(query, recentTurns, contextTurns)
  → L0：q' 嵌入一次，对检索宇宙（store.retrievable()：有效未压缩记录 + 有效节点，
        节点文本 = gist）精确 kNN，取 top l0TopK
  → CSLS：cue = 2·cos − r(q) − r(m)；r(q)=L0 池余弦均值，r(m)=item.r_m（节点 r_m 由第 7 步刷新）
          cold 记录/节点需 cue ≥ cueThreshold + coldCueBoost（唯一分层消费点）
          取 top cslsTopK
  → 精排：cross-encoder 对 csls 幸存文本批量打分（[0,1]，仅同查询内排序），取 top rerankTopK
  → MMR：λ·relevance − (1−λ)·max(与已选集的余弦)，relevance 缺失时以 cue 代理
  → top（默认 mmrTopK）+ suppressed（进过精排阶段但未进 top 者）
```

- 空宇宙直接返回空结果（不调嵌入/精排）；CSLS 后无幸存则不调精排端点。
- **C-5 精排失败降级**：rerank 端点异常不致命——沿用 cue 序进入 MMR（`relevance` 字段缺失），最终 score 投影按 `relevance ?? cue ?? cos` 取最好可用分。
- 消融档（设计 §7.1）：`base`/`csls`/`rerank` 提前返回对应阶段截断结果；`suppressed` 仅在 rerank/full 档有值。生产两通道恒用 `full`，消融档仅供 eval 脚本。
- 确定性：各级排序平局以 id 字典序决胜；MMR 同分取先遍历者。
- **ScoredCandidate 携带 `item: RetrievableItem`**（text/embedding/r_m/tier/createdAt/layer），下游（记账、工具输出、section 渲染）统一经 `item.layer` 区分情景层与语义层。

### 6.2 分层与门控

tier 只在两处被消费：cold 层的 cue 门槛（本节）与输出展示。记录 tier 落盘（写入时定型），节点 tier 由 `tierOf(node.S)` 在视图里现算。hot/warm 在行为上完全一致。`cueThreshold` (0.3) 只被 cold 门控消费。

### 6.3 expanded query 构造（buildExpandedQuery）

取 `recentTurns` 末尾 `contextTurns` 条、滤空后以 `\n---\n` 与 query 连接；`contextTurns <= 0` 时显式置空（规避 `slice(-0)` 取全数组的坑，源码有注释）。

## 7. 睡眠巩固周期（src/sleep-cycle.ts，P1）

设计 §2.3 七步的完整落地。**触发**在 runtime（§7.1），**批处理本体**在 sleep-cycle.ts，全部依赖注入（InternalLlm / EmbeddingProvider / 窄存储接口 `SleepStoreLike`），不依赖宿主框架，可离线单测。

### 7.1 触发门控（runtime.maybeSleep）

- 计数器 `newSinceSleep`：每次 `processTurn` 成功写入后累加 `written.length`；达到 `sleep.minNewMemories`（默认 10）即触发。
- 触发前检查：`sleep.enabled`、非 `sleeping`（**周期内不重入**）、聚类池（有效未压缩记录数）≥ `sleep.clusterMinSize`——池不足时**不清零计数**、等记忆继续累积。
- fire-and-forget：不阻塞回合；计数在运行前清零；`.finally` 中解除 `sleeping` 后**立即补判一次**（周期运行期间的新写入不丢失触发机会）。
- **不使用 `ctx.schedule` / `ctx.jobs`**：设计 §5.3 本就提供 turn/end 信号这一备选，README 已声明取舍（§2.1）。
- **B-8 失败语义细节**：计数在运行**前**清零——若周期整体抛错（已记日志），本轮累计的触发计数不回补，需再累计 `minNewMemories` 条新写入才重试。

### 7.2 确定性与常数（C-9）

- 聚类池与全库刷新都按 id 字典序遍历；连通分量、`maxNodeCos` 平局、簇排序均以 id 决胜——同库同配置结果可复现。
- **`M6_PROBES`**：|P| = 20 条多样化探针，设计 §3.6 固定值（如同 `RED_NEIGHBOR_TOP`），属度量工具常数、**不进 Config**。
- 节点 id 默认 `crypto.randomUUID()`，测试可注入 `newId`；`SleepStoreLike` 是 MemoryStore 的窄接口（`validMemories/validNodes/updateRecord/putNode/refreshNeighborhood/refreshNodeNeighborhood`）。

### 7.3 单簇流水（processCluster）

```
成员（按 id 序）
→ 第 2 步 gist 抽取（1 次 ctx.llm，{"gist": "..."}）→ gist 嵌入（1 次）
→ M6 epi 预计算（纯计算，见 7.5）
→ 第 3 步 QA 闸门：generateQaPairs（1 次，≤qaPairCount 对）→ 逐对 answerFromGist（各 1 次）
   → 平均 token 级 F1（qaF1，Han 单字 + 字母数字 token 多重集交叠）
   → 0 对 或 均值 < qaF1Threshold → 全簇标 incompressible，route='qa_failed'（簇保留）
→ 第 5 步 M6 闸门：gistEpi ≥ epiThreshold → 全簇标 incompressible，route='epi_failed'
   （摘要未去情景化，不可迁移；M6 前置于 M4 是有意排序：纯计算闸门先拦，
    可省一次 LLM 兼容复核调用，两闸都过才迁移、语义等价）
→ 第 4 步 M4 路由 + 第 6 步迁移：
   · 语义网络为空 → 无条件建首节点（引导路径；设计未定义空网情形，P1 政策）
   · con = z( gist 对网络峰值余弦 )，基线 = 最近 conWindow 条未压缩记录的峰值余弦分布
     （σ 下限 1e-9 防 0 除；基线空 → con=0 → 留情景层）
   · con > conAttachSigma → LLM 兼容复核（1 次）：通过 → 挂入（member_refs 追加、
     节点 S += attachGain）+ 成员压缩；不通过 → stayed
   · con < conNewNodeSigma 且簇均 imp ≥ conNewNodeMinImp → 建新节点（S = 簇均 imp）
   · 其余 → stayed（等下个巩固周期）
失败语义：单簇失败不中断整轮（记日志继续）；signal 中止则原样上抛。
```

### 7.4 闸门拒收语义（C-10）

`qa_failed` / `epi_failed` 都不是错误：簇保持原状继续可检索，全簇成员标 `flags.incompressible`。聚类阶段要求分量内**至少一名成员未标记**——全簇已标 = 上轮闸门已拒，需新成员加入才值得重试（防止对同一簇反复烧 LLM）。

### 7.5 M6 完整 epi（gistEpiScore）

`σ( z(实体密度) + z(时间表达密度) − z(G) )`，系数 a=b=c=1（设计固定）。三个特征都相对「当前有效未压缩情景记忆」分布做 z 标准化（`zScore` 带 σ 下限、空分布返 0）；G = 对 20 探针的平均余弦。z 化是刻意的：裸余弦跨嵌入模型不稳定，z 化后 `epiThreshold` 才有尺度不变的含义。写入路径记录上的 `epi` 仍是词法近似（§3.1）——完整公式只作用于 gist。

### 7.6 迁移与归档

- 建新节点：`putNode`（S=簇均 imp、r_m=0 待第 7 步刷新）→ 成员逐条 `updateRecord`：`flags.compressed_into = nodeId`、`flags.qa_passed = true`、`con_route` 定型（INV-6）。
- 挂入已有节点：`putNode({...attachTo, member_refs: 追加, S: +attachGain})` → 成员同上，`con_route = attached`。

### 7.7 第 7 步：全库统计刷新

即使本轮无簇也执行：对全部有效未压缩记录刷新 r_m/red，对全部有效节点刷新 r_m——新写入在周期之间漂移的邻域统计由此收敛（§4.5、B-2）。代价：每周期对全库做 O(n·kNN) 精确检索。

## 8. 自动注入通道内部（runtime.observeAgents + renderAutoSection）

### 8.1 生命周期

- `config.section.enabled === false` 时整条通道不注册（连 pendingQuery 监听一起省略）。
- 每个 `agent/created`：在该 agent 的**定域 context** 上注册 `system-prompt/assemble` waterfall 监听器——定域注册使监听器只收该 agent 的装配、且随 agent dispose 自动逆序清理（宿主契约）。
- `agent/inbox/claimed`（全局监听，按 source.kind==='user' 过滤）：记录每 agent 最新待处理人类输入 → `pendingQuery`；`agent/disposed` 时清除。
- **B-3 宿主边界**：若该 agent 作用域内有**complete section** 注册（如 agent preset 遮蔽），waterfall 返回后宿主会恢复 complete section 为唯一提示词——本插件 push 的记忆 section 会被**静默丢弃**。这是宿主明文契约（dsh-system-prompt index.d.ts assemble 事件注释），插件无对策，属于部署组合的固有权衡。

### 8.2 查询来源优先级

`pendingQuery.get(agentId)`（本轮 claimed 的最新人类输入）→ 回退到 `recent` 中最近一条 user 消息 → 两者皆无则返回空串（不注入）。

### 8.3 装配期行为

```
listener(assembly, context, next):
  downstream = await next()          // 必须先放行（不拦截流水线）
  try:
    text = renderAutoSection(agentId, context.signal)   // 信号只作用于本次装配
    if text: downstream.sections.push({ name:'dsh-mem', text })
  catch: log 后放行原样 downstream   // 检索失败静默，绝不破坏装配
  return downstream
```

### 8.4 同轮缓存与记账

- **C-7 缓存键 = expanded query 字符串**：同轮内后续 step（工具调用后重新装配）展开查询不变 → 复用 `lastResult`，不重复调用嵌入/重排端点、**不重复记账**；查询或 recent 变化 → 重跑全链。
- 每次全新检索触发一次 `recordUse`（fire-and-forget）：top 记录 `used_count+1 / last_used_at / last_cue_quality`，suppressed 记录 `suppressed_count+1`（每查询至多计一次，对齐设计 §2.1 ε 语义）。目标记录已被软失效时静默吞掉更新失败。**语义层命中不记账**（节点无 counters，P2）。
- 通道不使用 `exec.agent.inject` / `agent.inject()`——自动上下文按设计走 section，不走 inject 通道。
- section 渲染（`formatMemories`）：语义层命中追加 ` type=gist` 标记，模型可区分原始记忆与蒸馏 gist。

## 9. memory_search 工具内部（src/tool.ts）

### 9.1 注册与开关

`config.tool.enabled` 控制；与 section 通道互相独立（两者都关时插件仍写入记忆并运行睡眠周期）。

### 9.2 规范输出（SearchOutput）

```
{ query, expandedQuery,
  memories: [{ id, text, score, cue?, tier('hot'|'warm'|'cold'),
               layer('episodic'|'semantic'), createdAt }],
  suppressedCount }
```

- `output.schema` 显式 `additionalProperties:false`（对象节点硬性要求）；`score = relevance ?? cue ?? cos`（最好可用分）；`layer` 区分原始记忆与睡眠周期蒸馏的 gist。
- `render` 是规范值的**纯投影**：空数组 → 'No relevant memories found.'；编号行，语义层追加 ` gist` 标记。UI 格式不进规范值。
- `presentCall` 返回 `generic` 卡（kind 'search'）、`presentResult` 返回 `generic` 卡——均为纯函数。
- `limit` 参数（integer ≥1）覆盖默认 `tool.maxResults`，直接作为 `topK` 传入检索器。
- `execute` 全程携带 `exec.signal`；`exec.agent` 只读（取 recentTurns），不调用 inject。

### 9.3 记账

每次 execute 触发 `onRetrieved`（即 `recordUse`，语义同 §8.4，含「语义层不记账」）——工具路径与自动路径的记账规则一致，但互不复用缓存（各自独立检索）。

## 10. 内部 LLM 调用（src/llm.ts，CordisLlm）

- **C-8 终态判定契约**：`ctx.llm` 契约下适配器/提供方失败被规范化为**终态 error/aborted finish 块**，迭代本身不抛错——必须经 `assembler.finish` 读取后显式抛错（携带 code/status），否则真实失败会被误报为空回复。空回复同样按失败抛。
- 每次调用构造独立的 `createUserMessage`（source kind 'user'）+ `system` 文本；`provider/model/temperature/maxTokens` 全部来自 Config；`signal` 存在时透传。
- `config.llm.provider` 必须是宿主 ctx.llm 上**已注册适配器的路由名**（如 `deepseek`）；凭据由宿主适配器解析，插件不接触 key。
- **P1 起消费方共 7 类**：候选抽取、M5 判分、矛盾判定（写入管线）；gist 抽取、QA 对生成、gist 作答、M4 兼容复核（睡眠周期）。写入管线与睡眠周期各持一个 `CordisLlm` 实例（同一 Config 路由）。不设置 `purpose` 字段。

## 11. 嵌入/重排客户端（src/embedding.ts）

dsh 无嵌入/rerank seam（ref capability-seams 全表核实）——二者是**插件自有 HTTP 依赖**，端点/模型/维度全在 Config。

- **协议**：`/embeddings` OpenAI 兼容（`{model, input[]}`，按返回 `index` 对齐、缺口/数量不符即报错）；`/rerank` Cohere/Jina 式（`{model, query, documents, top_n}`，读 `results[].relevance_score` 并夹取 [0,1]）。
- **C-6 归一化职责**：http 模式在客户端本地归一化（不信任服务端单位长度）；deterministic 替身同样归一化。所有下游（索引、余弦、MMR 相似度、M6 探针相关度）依赖此契约。
- **超时合并**：`AbortSignal.any([caller.signal, AbortSignal.timeout(timeoutMs)])`。
- **deterministic 模式**：FNV-1a 词袋哈希双桶嵌入 + 余弦式 rerank 替身——同文本同向量、只验证管线连通性，**数值无语义意义**（README 与两个 eval 输出均已声明）。
- **P1 新增消费**：gist 嵌入、M6 探针集嵌入（每周期一次、仅当有簇）。

## 13. 生命周期与并发

**启动序列**：`apply` → `MemoryRuntime.start()`（异步、失败仅记日志不杀宿主）→ 开 storage unit（无 kv facet 则响亮报错）→ `ctx.effect` 注册 unit 关闭 disposer → 建内存库/检索器/写入管线/睡眠周期 → 注册 session 观察、agent 观察、（tool.enabled 时）memory_search → 打印 `started: N valid memories in store`。

**重载**：插件卸载（HMR 或依赖消失）→ 全部 effect 逆序清理（事件监听、工具注册、unit close）。睡眠周期无独立注册——它只是运行中的 Promise，重载后新实例以介质现状重建（周期内未完成的写入已按 INV-4 逐条落盘）。

**进程内状态**：
- `sessions: Map<sessionId, {recent, pending, watermark, lastExpandedQuery?, lastResult?}>`——**B-4 无上限**：不随会话销毁清理（agent/disposed 只清 pendingQuery）；每会话留存一个滑动窗口，常驻宿主下缓慢累积。
- `pendingQuery: Map<agentId, text>`——随 agent 生命周期清理。
- `newSinceSleep: number` + `sleeping: boolean`——睡眠触发门控（§7.1）；B-8 记录失败周期不清回计数。

**并发写链全景**（C-1c）：写入管线（每 turn/end）× 使用记账（每检索）× 睡眠周期（门控）——三条 fire-and-forget 链，跨链同记录并发 `updateRecord` 的丢失更新窗口已被所有者接受（README 取舍段）。

## 15. 审核发现与建议（2026-10-24，P1 复核后状态）

| F-1 | `inject` 声明 `sessions` 但 `ctx.sessions` 全库无消费（`this.sessions` 是插件自有 Map）——多余的**必需**依赖，理论上会因缺该服务而 PENDING | 低 | **仍在**（index.ts 未改） |

| F-3 | `sessions` Map 无上限增长（B-4） | 低 | **仍在** |
